Prevsi · Healthcare

From prototype to clinical platform

Turning a polished click-through demo into a production system for patient care, clinical operations, privacy, and deployment.

Starting from the design, not from scratch

Prevsi arrived with a strong design system and a clear patient experience, but authentication, saving, and messaging were mocked. We treated the source design package as a read-only contract, then built typed design tokens and a shared Storybook component library. That preserved the quality of the prototype while giving every interface a reusable implementation.

A pnpm and Turborepo monorepo gave the patient app, admin console, and API shared contracts without letting them reach into one another’s internals. The result was a system that could evolve without visual drift or architectural shortcuts.

Making identity, data integrity, and privacy real

Patients and staff sign in through Amazon Cognito email one-time codes, with optional social sign-in for patients. Session persistence, resend cooldowns, and idle-timeout sign-out handle the less obvious edges of passwordless authentication.

Enrollment requests use idempotency keys and DynamoDB transactions, so retries return the original receipt rather than creating duplicate patients. Most importantly, every declared PHI field is envelope-encrypted before it reaches storage. Each write receives an AES-256-GCM data key wrapped by AWS KMS, with authenticated context bound to its entity and field.

Compliance was designed as a property of the system, not a checklist applied after launch.

Raw Social Security numbers never leave the API by default. Full-value access is audited, existing plaintext was migrated, and the production API refuses to start without KMS configured.

Building the clinical operations layer

Behind the patient portal, we built multi-clinic tenancy, permission-based roles, durable auditing, and an EMR workspace for results, notes, prescriptions, medications, allergies, diagnoses, appointments, and two-way care-team messaging.

A standalone admin console uses its own Cognito client and protected API surface. Super-admins can invite staff through SES, while intentionally short-lived, in-memory admin sessions reduce exposure. Patients receive a status timeline, released results, appointments, receipts, and self-service data deletion with a grace period.

Infrastructure as product

Terraform defines DynamoDB, Cognito, ECR, ECS Fargate, the application load balancer, KMS, and SES. Frontends deploy through AWS Amplify, while GitHub Actions serialize infrastructure and image deployments. Playwright screenshot diffs catch visual regressions before a client does.

The portal ships in English, Spanish, and French, including the intake flow, localized metadata, hreflang alternates, structured data, and sitemap support.

The result

Prevsi now operates as a production-grade, multi-tenant clinical platform: a multilingual patient portal, complete clinical workspace, dedicated admin console, auditable operations, encrypted PHI, and repeatable infrastructure.
